Without this one tag, phones pretend to be a 980px desktop and zoom out — the classic “tiny website”. It must come before any CSS so the layout meets the device at its true width.

broken
<!-- no viewport meta — phone renders
     a 980px canvas and zooms out -->
fixed 
<meta name="viewport"
      content="width=device-width, initial-scale=1,
               viewport-fit=cover">

A 1200px wrapper is a 200px puddle on a phone. Width should state a maximum, never a minimum — and the gutter should breathe with the viewport too.

broken
.page { width: 1200px; }
fixed 
.page {
  width: min(100% - 2.5rem, 1200px);
  margin-inline: auto;
}

Type set in hard pixels ignores the viewport entirely — it overflows on phones and whispers on monitors. One clamp() line scales smoothly from 320px to 2560px. The headline at the top of this page is the proof.

broken
h1 { font-size: 64px; }  /* overflows ≤ 412px */
fixed 
h1 {
  font-size: clamp(2.7rem, 8vw + .5rem, 8.2rem);
  line-height: .98;
}

Four hardcoded columns turn to soup under 500px. auto-fit + minmax() lets the browser do the collapsing — watch it work downstairs in the reflow room.

broken
.cards { grid-template-columns: repeat(4, 1fr); }
fixed 
.cards {
  grid-template-columns:
    repeat(auto-fit, minmax(min(100%, 13rem), 1fr));
}

One 2400px hero, three layout fractures. Two lines of CSS stop the overflow; srcset + sizes stop the bandwidth crime; picture art-directs the crop when it matters.

broken
<img src="hero-2400.jpg" width="2400" alt="">
fixed 
img { max-width: 100%; height: auto; }

<img srcset="hero-480.jpg  480w,
             hero-960.jpg  960w,
            hero-1600.jpg 1600w"
     sizes="(max-width: 700px) 100vw, 700px"
     src="hero-960.jpg" alt="…">

A 700px table on a 375px screen is a sideways-scrolling trap. Below 640px, flip every row into a labelled stack — same markup, new silhouette. The timetable in section 03 does exactly this.

broken
/* a 700px table on a 375px screen */
.table-wrap { overflow-x: scroll; }  /* the surrender */
fixed 
@media (max-width: 640px) {
  .tt thead { display: none; }
  .tt, .tt tr, .tt td { display: block; }
  .tt td::before {
    content: attr(data-label);  /* column name */
  }
}

A 24px link is a coin-flip for a thumb. 44 × 44px minimum, generous spacing, and touch-action: manipulation so taps feel instant. Section 04 measures it live.

broken
.icon-btn { width: 24px; height: 24px; }
fixed 
.icon-btn {
  min-width: 44px; min-height: 44px;
  touch-action: manipulation;
}

Mobile browsers collapse and grow; 100vh doesn't follow. And edge-to-edge designs get eaten by notches and home indicators. svh/dvh plus env(safe-area-inset-*) fix both — this page's header and footer wear them right now.

broken
.hero { height: 100vh; padding: 12px; }
fixed 
.hero { min-height: 100svh; }
@supports (height: 100dvh) {
  .hero { min-height: 100dvh; }
}
.pad-safe {
  padding: max(1rem, env(safe-area-inset-top))
           max(1rem, env(safe-area-inset-right))
           max(1rem, env(safe-area-inset-bottom))
           max(1rem, env(safe-area-inset-left));
}

A hamburger that opens but never closes cleanly — no Escape key, no scroll lock, focus lost into the void. The pattern below runs this very page's menu under 860px. Try it.

broken
menuBtn.onclick = () => menu.style.display = 'block';
/* …and that's it */
fixed 
btn.addEventListener('click', () => {
  const open = menu.classList.toggle('open');
  btn.setAttribute('aria-expanded', open);
  html.classList.toggle('locked', open);
});
addEventListener('keydown', e => {
  if (e.key === 'Escape') closeMenu();
});

04 — Thumbs & notches

Built for thumbs, safe for notches.

Touch is the primary pointer on most of the planet. Everything below is measured, toggleable and honest about its own hit area.

Hit-zone lab Every control below is at least 44 × 44px. Flip the switch to trace the real tap area; the small pair shows what rejection looks like.

24px — rejected
saved × 0
  • Dynamic viewport

    100vh lies on mobile; 100svh and 100dvh track the real visible viewport as the URL bar collapses. This page's menu uses them.

  • Safe areas

    With viewport-fit=cover, env(safe-area-inset-*) keeps content clear of notches and home bars — the header above and the footer below both wear it.

  • Tap, don't wait

    touch-action: manipulation plus ≥44px targets removes the double-tap hesitation — and hover is never the only path to a control.

  • Motion consent

    Every animation here — the ticker included — switches itself off under prefers-reduced-motion: reduce.

fixed 
/* the dvh + safe-area pattern, verbatim */
.hero { min-height: 100svh; }
@supports (height: 100dvh) {
  .hero { min-height: 100dvh; }
}
.foot {
  padding-bottom: max(1.6rem,
    env(safe-area-inset-bottom));
}
